# Career Targeting — Global Remote, Contract & Long-Term Roles

## Purpose

This document captures the career-search requirements discussed for Hunt-Job. The target is a stable, technically challenging role that can strengthen cloud, Kubernetes, platform engineering and SRE depth while remaining compatible with long-term career planning.

## Target Role Tracks

### Primary technical track
- Staff DevOps Engineer
- Staff Platform Engineer
- Staff SRE
- Cloud / Kubernetes Platform Engineer
- Principal / Lead Platform or SRE Engineer

### Secondary track
- Cloud / DevOps Architect
- Principal Architect where the role remains technically deep and hands-on

### Selectively consider
- Engineering Manager / DevOps Manager roles where the work is stable, the scope is clear, and the role does not eliminate technical growth.

## Global Remote Opportunity Types

Hunt-Job should distinguish:
- Remote-from-India permanent employment
- International company hiring employees in India
- Remote contractor roles
- Contract-to-hire roles
- EOR-based employment
- Part-time / consulting / project work

Remote must not be treated as equivalent to "work from anywhere". The system should capture geographic eligibility, employment model, work authorization, time-zone overlap and sponsorship requirements.

## Company Preference

Target established companies rather than very early-stage startups.

Suggested default filter:
- Company age: 3+ years
- Prefer 5+ years where evidence is available
- Capture founding year and company maturity as metadata
- Do not reject a role solely because the company is young when the user explicitly overrides the filter

## Technical Learning Fit

The job evaluator should identify whether a role materially increases exposure to:
- AWS / cloud architecture
- Kubernetes / EKS
- Terraform / Infrastructure as Code
- GitOps
- Platform engineering
- SRE / reliability engineering
- Observability
- CI/CD and developer platforms
- Containers
- Security and FinOps

This is a career-growth signal, separate from the existing job-fit score.

## Stability Signals

Capture evidence rather than inventing a "stability score". Useful signals include:
- Permanent vs temporary employment
- Contract length
- Contract-to-hire wording
- Funding / company maturity where verifiable
- Hiring team / business unit
- Whether the role is tied to a named long-term product or platform
- Layoff / restructuring signals when reliably sourced
- Benefits and employment protections
- Expected on-call / workload expectations

## Compensation Capture

Normalize compensation where possible:
- Currency
- Base salary
- Variable / bonus
- Equity
- Contract hourly / daily / monthly rate
- Benefits
- Employment model
- Tax responsibility where explicitly stated

Do not infer compensation when the posting does not provide it. Mark unknown fields as unknown.

## Profile Positioning

The candidate profile should support two parallel narratives:

### Senior technical / platform narrative
15+ years IT experience with DevOps, AWS, CI/CD, infrastructure automation, containers, observability and platform/SRE responsibilities.

### AI-enabled engineering narrative
Open-source and personal engineering work demonstrating practical AI-assisted automation and software engineering in addition to core DevOps capability.

Examples of portfolio evidence can be attached to the profile as projects, repositories, outcomes and technologies rather than as unsupported claims.

## Hunt-Job Feature Direction

Future scoring/filtering should include:
- employmentModel
- remoteEligibility
- locationEligibility
- workAuthorization
- sponsorship
- contractDuration
- contractToHire
- companyFoundedYear
- companyAge
- companyMaturity
- learningFit
- cloudDepth
- kubernetesDepth
- platformEngineeringFit
- stabilitySignals

The application should present these as transparent fields and reasons so the user can make the final decision.

## Operating Goal

The system should optimize for a sustainable, high-quality search rather than maximum application volume:
1. Discover relevant jobs.
2. Remove jobs the candidate cannot legally or practically work.
3. Evaluate technical growth and stability separately from general fit.
4. Tailor the profile/resume.
5. Track applications and outcomes.
6. Learn from user feedback without silently changing the candidate's preferences.
